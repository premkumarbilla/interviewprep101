Figma Coding Prep

Figma's coding problems model pieces of its own editor: undo history, the layers panel, frames on a canvas, sharing permissions. They're built in stages, and interviewers weigh clean class design and clear narration as much as the algorithm. This page groups reported problem types by pattern, with Figma-style prompts to practice and LeetCode problems that build the same skills, plus a 13-day plan.

How to run each problem

Clarify, then design

Restate the problem and ask about edge cases. Before coding, name your class, its methods and data structures, and say how a follow-up like batching or redo would fit.

Simple and correct first

Build part 1 cleanly, then extend. A finished part 1 with a clear plan for part 2 beats a half-built clever solution.

Talk the whole time

Narrate what each line does and why. Reported rejections cite silent coding more than wrong answers. If you're stuck, say what you're trying.

Test out loud

Walk one normal and one edge case through your code: empty input, a missing key, undo with nothing to undo, ties when sorting. Close with time and space for each method.

13-day plan

About two hours a day. Undo/redo comes first because it's the most often reported problem type. Do each mock out loud, timed at 45 minutes, in the editor you'll use on the day.
